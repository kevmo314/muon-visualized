Muon, visualized

Muon takes the momentum matrix that SGD would use, and replaces it with the nearest orthogonal matrix, so every direction in the update gets the same size step. Why does that help, and what does it cost? Pick an explanation from the research, then go break things in the 3D lab.

SGD-momentumAdamWMuon

AdamW: normalize each entry

m ← β₁m + (1−β₁)g
v ← β₂v + (1−β₂)g²
W ← W − η·( m̂ / (√v̂ + ε) + λW )

Every coordinate is rescaled on its own. Big for vectors, but it sees a weight matrix as a bag of numbers. Its idea of "a direction" depends on which basis the matrix happens to be written in.

Muon: normalize each singular direction

M ← βM + G                 (momentum)
O ← NewtonSchulz₅(M) ≈ UVᵀ  (M = USVᵀ)
W ← W − η·O

The SVD keeps the momentum's input/output directions (U, V) and throws away the singular values S. Five cheap matmul iterations approximate this without ever computing an SVD.

Tradeoffs you can't see in a 6×6 toy

  • PRO Memory. Muon keeps one momentum buffer per matrix. AdamW keeps two (m and v).
  • CON Hidden matrices only. Jordan et al. apply Muon to 2D hidden-layer weights. Embeddings, the output head, and gains/biases still go to AdamW (or SGD), so you tune two optimizers.
  • CON Extra compute and communication. Newton–Schulz costs a few matmuls per matrix per step. Under sharded training each full matrix must be gathered before orthogonalizing. Moonshot handles this with a distributed variant built on ZeRO-1.
  • TUNE Update scale. A raw orthogonal update has RMS ≈ 1/√max(A,B), which depends on the matrix's shape. Moonshot rescales it by 0.2·√max(A,B) so AdamW's learning rate and weight decay transfer directly.
